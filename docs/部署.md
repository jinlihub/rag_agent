# 部署文档

> 记录 2026-11-10 在实验室 GPU 服务器上的完整部署过程，含环境要求、操作步骤与踩坑记录。
> 目标机器：阿里云 ECS（16 vCPU / 128 GiB / NVIDIA L20 48G / Ubuntu 24.04）

## 1. 架构

```
浏览器
  │
  ▼
Nginx :8080
  ├─ /        → frontend/dist 静态文件（Vue 3 产物）
  └─ /api/    → 反向代理 → uvicorn :8000（FastAPI）
                              ├─ MySQL :3306        （业务表 / 标的物 / 企业 / 法规）
                              ├─ PostgreSQL :5432   （含 subject 列的项目库）
                              └─ data/index/*.npz   （向量索引，进程内加载）
```

采用**单机多容器**：应用跑在 systemd，数据库跑在 Docker，两层解耦，数据库重启不影响应用。

## 2. 环境要求

| 项 | 要求 | 本机实况 |
| --- | --- | --- |
| 系统 | Linux（Ubuntu 22.04+） | Ubuntu 24.04 |
| Python | **3.13**（`pyproject.toml` 要求） | 系统 3.12.3，用 uv 另装 3.13.18 |
| Node | **20.19+ 或 22.12+**（Vite 7 要求） | v26.13.0 |
| Docker | 20+ | 29.8.0 |
| Nginx | 1.18+ | 1.24.0 |
| 内存 | ≥ 8 GiB | 123 GiB |
| 磁盘 | ≥ 20 GiB | 917 GiB 可用 |
| 外网 | 能访问智谱 API、npm/pip 镜像 | 正常 |

**Python 版本不要用系统自带的**。Ubuntu 24.04 预装 3.12，低于项目要求，用 uv 独立安装即可（见 §3.1）。

## 3. 部署步骤

以下路径以 `/home/admin/group_3/xingshuai/rag_agent` 为例，按实际调整。

### 3.1 工具链

```bash
# uv（Python 包与版本管理）
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc

# 项目要求的 Python 3.13（装在 ~/.local/share/uv/python，不动系统 Python）
uv python install 3.13

# Node（apt 版本太旧，用官方二进制 + 国内镜像）
cd /tmp
V=$(curl -sL https://npmmirror.com/mirrors/node/index.json \
    | python3 -c "import sys,json;d=json.load(sys.stdin);print(next(x['version'] for x in d if x.get('lts')))")
curl -LO "https://npmmirror.com/mirrors/node/$V/node-$V-linux-x64.tar.xz"
tar -xf "node-$V-linux-x64.tar.xz"
rm -rf ~/.local/node && mv "node-$V-linux-x64" ~/.local/node
echo 'export PATH=$HOME/.local/node/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

# npm 镜像
npm config set registry https://registry.npmmirror.com
```

验证：`uv --version`、`node -v`（需 ≥ 22.12）、`npm -v`。

### 3.2 数据库（Docker）

拉镜像时 Docker Hub 常被 DNS 污染，走国内镜像站再打 tag：

```bash
docker pull docker.m.daocloud.io/library/mysql:8.0
docker tag docker.m.daocloud.io/library/mysql:8.0 mysql:8.0

docker pull docker.m.daocloud.io/library/postgres:18
docker tag docker.m.daocloud.io/library/postgres:18 postgres:18
```

启动容器（名字加个人前缀，避免同服务器多人冲突）：

```bash
docker run -d --name xingshuai-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=<你的密码> \
  -e MYSQL_DATABASE=rag_cleaned \
  -e TZ=Asia/Shanghai \
  -v xingshuai-mysql-data:/var/lib/mysql \
  --restart unless-stopped \
  mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci

docker run -d --name xingshuai-pg \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=<你的密码> \
  -e TZ=Asia/Shanghai \
  -v xingshuai-pg-data:/var/lib/postgresql \
  --restart unless-stopped \
  postgres:18
```

**PostgreSQL 18 的挂载点是 `/var/lib/postgresql`，不是 `/var/lib/postgresql/data`**——用错会不停重启，详见 §4.1。

`--restart unless-stopped` 让容器随宿主开机自启，无需手工干预。

### 3.3 数据导入

```bash
cd ~/group_3/xingshuai/rag_agent

# 1) 标的物 + FAQ（脚本从项目根目录读 xlsx，需先复制）
cp data/processed/招标采购标的物信息提取训练数据.xlsx .
cp data/processed/问题答案样例数据0113.xlsx .
uv run python scripts/import_xlsx_to_mysql.py

# 2) 应用表（user_account / qa_record / session_memory / tracking_event）
uv run python scripts/init_db.py

# 3) 法规 / 政策 / 企业表（数据不在仓库里，从现有库导出导入）
uv run python _export/_import.py

# 4) 项目数据进 PostgreSQL（8789 行，含 subject 列）
uv run python src/database/to_postgresql.py

# 5) 构建向量索引（调 embedding API，约 2~5 分钟）
uv run python scripts/build_index.py
```

**第 3 步说明**：`legal_articles` / `legal_metadata` / `policy_*` / `enterprise_*` 六张表的建表语句与数据都不在代码仓库中（原环境由负责人直接建库）。需要从已有 MySQL 导出为 JSONL 再导入，导出脚本见 `_export/`（含 `_manifest.json` 与 `_import.py`）。

索引产物落在 `data/index/`：`legal.npz`（4954 条）、`policy.npz`（643 条）、`faq.npz`（80 条），各配一个 `.meta.jsonl`。

### 3.4 后端托管（systemd）

先确认 uv 绝对路径（`which uv`），再写 unit：

```bash
sudo tee /etc/systemd/system/rag-agent-xingshuai.service > /dev/null <<'EOF'
[Unit]
Description=rag_agent FastAPI
After=network.target docker.service
Requires=docker.service

[Service]
Type=simple
User=admin
WorkingDirectory=/home/admin/group_3/xingshuai/rag_agent
Environment="PATH=/home/admin/.local/bin:/usr/local/bin:/usr/bin:/bin"
ExecStart=/home/admin/.local/bin/uv run uvicorn rag_agent.api.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5
StandardOutput=append:/home/admin/group_3/xingshuai/rag_agent/logs/app.log
StandardError=append:/home/admin/group_3/xingshuai/rag_agent/logs/app.err.log

[Install]
WantedBy=multi-user.target
EOF

mkdir -p ~/group_3/xingshuai/rag_agent/logs
sudo systemctl daemon-reload
sudo systemctl enable --now rag-agent-xingshuai
```

要点：

- `--host 0.0.0.0`（不是 127.0.0.1），否则 Nginx 之外的访问进不来
- 不要加 `--reload`，生产环境无用且占资源
- `Restart=always` + `RestartSec=5`：崩溃后 5 秒自动拉起
- 共享服务器上给 unit 带个人后缀（如 `rag-agent-xingshuai`），避免和他人冲突。**服务名必须完全一致**——名字查错时 `systemctl is-active` 只返回 `inactive`，不会报「服务不存在」，很容易误判成服务挂了

### 3.5 前端构建

```bash
cd ~/group_3/xingshuai/rag_agent/frontend
npm install
npm run build
```

`npm run build` 实际执行 `vue-tsc --noEmit && vite build`，**类型检查不通过不会打包**。产物在 `frontend/dist/`。

### 3.6 Nginx 静态托管 + 反代

共享服务器上 80 端口通常已被 `default` 站点占用，改用 8080，**不要删别人的 `sites-enabled/default`**。

```bash
sudo tee /etc/nginx/sites-available/rag-agent-xingshuai > /dev/null <<'EOF'
server {
    listen 8080;
    server_name _;

    root /home/admin/group_3/xingshuai/rag_agent/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }

    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1024;
}
EOF

sudo ln -sf /etc/nginx/sites-available/rag-agent-xingshuai /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

两个配置不可省：

| 配置 | 作用 |
| --- | --- |
| `proxy_buffering off` | 关闭缓冲，SSE 才能逐字推送；否则前端等 20 秒后整段弹出 |
| `try_files $uri $uri/ /index.html` | Vue Router history 模式必需，否则刷新 `/chat` 会 404 |

### 3.7 目录权限

Nginx worker 以 `www-data` 运行，读不到权限为 700 的家目录会返回 500：

```bash
sudo chmod o+x /home/admin                                            # 允许穿过家目录
sudo chmod -R o+rX ~/group_3/xingshuai/rag_agent/frontend/dist        # 给产物加读权限
sudo -u www-data ls -l ~/group_3/xingshuai/rag_agent/frontend/dist/index.html
```

`o+x` 只给「穿过」权限，不给读列表（`ls` 仍不可用）；私密目录（`.ssh` 等）自身是 700，不受影响。

## 4. 踩坑记录

### 4.1 PostgreSQL 18 的卷挂载点变了

症状：容器 `Restarting (1)`，日志报 `there appears to be PostgreSQL data in /var/lib/postgresql/data`。

原因：PG 18 起数据目录改为 `/var/lib/postgresql/18/docker`，官方要求挂载**父目录** `/var/lib/postgresql`。

```bash
# 错误
-v xingshuai-pg-data:/var/lib/postgresql/data
# 正确
-v xingshuai-pg-data:/var/lib/postgresql
```

### 4.2 Docker Hub 域名被污染

症状：`docker pull mysql:8.0` 报 `dial tcp 157.240.2.36:443: i/o timeout`（157.240.2.36 是 Facebook 网段）。

解决：改用 `docker.m.daocloud.io/library/...` 拉取后再 `tag`。**不建议改全局 `/etc/docker/daemon.json`**——共享服务器上会影响他人。

### 4.3 curl 缺 `-L` 拿到 302 页面

症状：`curl -s https://npmmirror.com/mirrors/node/index.json` 只返回 154 字节的 `<html>302 Found</html>`，导致后续 `grep` / `json` 解析全部失败。

解决：统一加 `-L` 跟随重定向。

### 4.4 Node 版本被 Vite 7 卡住

Vite 7 的 `engines` 是 `^20.19.0 || >=22.12.0`。Ubuntu 源的 nodejs 是 18.x，手工选 v22.11.0 也差一点。

解决：取最新 LTS（当前 v26.13.0），装完务必 `node -v` 确认。

### 4.5 Nginx 返回 500（Permission denied）

症状：`/api/health` 正常 200，但 `/` 返回 500，`error.log` 报 `stat() ... failed (13: Permission denied)`。

原因：家目录 `/home/admin` 是 `drwxr-x---`，`www-data` 进不去。

解决：见 §3.7。

### 4.6 Ctrl+C 会杀死 PostgreSQL

现象：本地用 `pg_ctl start` 启动后，在终端按 Ctrl+C，PostgreSQL 一并退出，日志出现 `background worker terminated by exception 0xC000013A`。

原因：`pg_ctl` 启动的 postgres 与终端共享控制台进程组，Ctrl+C 会发给整个进程组。

解决：用 `DETACHED_PROCESS` 启动（见本机脚本 `scripts/start_pg.py`），或让容器托管（服务器方案即如此）。

### 4.7 导入脚本的路径假设

`import_xlsx_to_mysql.py` 从**项目根目录**读两个 xlsx：

```python
_BID_XLSX = _ROOT / "招标采购标的物信息提取训练数据.xlsx"
_FAQ_XLSX = _ROOT / "问题答案样例数据0113.xlsx"
```

但文件实际放在 `data/processed/`，需先 `cp` 到根目录，否则 `FileNotFoundError`。

### 4.8 数据不在仓库里

法规（4772 行）、政策（413 行）、企业（21754 行）三组表在代码仓库中**既没有建表语句也没有数据**，只有运行期依赖。新环境必须从既有库导出，无法自举。

### 4.9 其他零碎

| 现象 | 原因 |
| --- | --- |
| 健康检查 404 | 路径是 `/api/health`，不是 `/health` |
| 登录后仍提示"未登录" | 响应字段是 `access_token`，不是 `token` |
| `systemctl` 显示 inactive | 把 `restart` / `stop` 连着执行了，最后一条 `stop` 生效 |
| `is-active` 返回 inactive 但服务明明在跑 | 服务名查错（如查 `rag-agent`，实际是 `rag-agent-xingshuai`）。**不存在的 unit 不报错，只返回 inactive**，先 `systemctl list-unit-files \| grep -i rag` 确认全名 |

## 6. 已知限制

| 项 | 说明 |

| 外网访问 | 阿里云安全组未放行 8080，需管理员在控制台加规则；临时可用 SSH 隧道 `ssh -L 18080:localhost:8080` |
