## 1. 统计口径

### 1.1 四类行数的定义

| 指标 | 定义 |
| --- | --- |
| **物理行** | 文件总行数，包含空行与注释行 |
| **空行** | `strip()` 后为空的行程数（含只含空白的行） |
| **注释行** | **纯注释行**——该行的非空白内容全部是注释或文档字符串 |
| **代码行** | `物理行 − 空行 − 注释行` |

**关于「行尾注释」**：`x = 1  # 说明` 这类行算作**代码行**，不计入注释行。理由是它包含可执行语句。

### 1.2 各语言注释的识别方式

| 类型 | 识别方式 | 说明 |
| --- | --- | --- |
| `.py` | `tokenize` 取 COMMENT token + `ast` 取文档字符串 | 文档字符串（模块/类/函数首行说明）计入注释行；若字符串出现在赋值语句中，仍算代码 |
| `.ts` / `.js` | 行级状态机 | 识别 `//` 与跨行 `/* ... */` |
| `.vue` | 行级状态机 | 识别 `//`、`/* ... */`，以及模板中的 `<!-- ... -->` |
| `.css` / `.scss` | 行级状态机 | 识别 `/* ... */` |
| `.html` | 行级状态机 | 识别 `<!-- ... -->` |
| `.sh` | 行级状态机 | 识别 `#`，跳过首行 shebang |
| `.md` | 不做注释识别 | Markdown 无统一注释语法，`<!-- -->` 未单独统计，全部非空行计为代码行 |

### 1.3 排除范围

**排除的目录**（依赖、产物、缓存、外部资源、数据）：

```
.venv/           Python 依赖
node_modules/    前端依赖
dist/            前端构建产物
__pycache__/     Python 字节码缓存
.git/            版本库
.run/            服务运行日志与 PID
.extract/        PDF/PPT 提取的图片与文本
data/            数据文件（xlsx / jsonl / npz），非代码
build/ .vite/ .pytest_cache/ .mypy_cache/ .ruff_cache/
.obsidian/ .claude/ .idea/ .vscode/   编辑器与工具配置
```

**排除的文件**（锁文件、自动生成、压缩产物）：

| 文件 | 原因 |
| --- | --- |
| `package-lock.json` | 依赖锁文件，由包管理器生成（约 2800 行，若不排除会使 json 统计失真 50 倍） |
| `uv.lock` | 依赖锁文件 |
| `*.d.ts`（如 `auto-imports.d.ts`、`components.d.ts`） | 由构建插件自动生成 |
| `*.min.js` / `*.min.css` | 压缩产物 |
| `_count_loc.py` | 统计脚本自身，避免自我计入 |

### 1.4 纳入范围与分组

| 分组 | 路径 | 性质 |
| --- | --- | --- |
| 后端业务代码 | `src/rag_agent/`、`src/database/` | 线上服务的实际代码 |
| 前端业务代码 | `frontend/src/` | 线上页面的实际代码 |
| 数据加工脚本 | `batch/` | 离线数据处理流水线 |
| 运维/一次性脚本 | `scripts/`（不含 ppt 相关） | 建索引、导数据、冒烟测试 |
| 评估体系 | `evals/` | 用例回放与评审 |
| 演示材料脚本 | `scripts/` 中文件名含 `ppt` 的部分 | 生成汇报 PPT 的一次性工具，与业务无关 |
| 文档 | `docs/`、`README.md` | 设计文档与技术说明 |
| 根目录/其他 | `start.sh`、`pyproject.toml`、`db.py`、前端配置 | 配置与启动脚本 |

**为什么把「演示材料脚本」单列**：`make_ppt.py`、`pptx_part1~3.py`、`shoot_ppt.py`、`preview_ppt.py` 六个文件共 1520 行，是制作汇报材料用的，与系统功能无关。若混入运维脚本，会让该类虚高 66%，误导对工程量的判断。

### 1.5 两点需要说明的偏差

1. **文档字符串会拉高注释行**。Python 模块级与函数级说明被计入注释行（例如 `agent.py` 有 46 行注释，其中大部分是模块顶部的行为说明）。因此「注释率」反映的是**说明性文字占比**，不等于"代码里写了多少行内解释"。
2. **本文件自身未计入**。统计执行时 `代码行数统计.md` 尚未生成；若重新统计，总数会再增加约 200 行。

## 4. 结果分析与观察

### 4.1 前后端规模接近 1:1

| 端 | 代码行 | 文件数 | 单文件均值 |
| --- | ---: | ---: | ---: |
| 后端业务 | 2,737 | 41 | 67 |
| 前端业务 | 2,437 | 19 | 128 |

后端 41 个文件平均 67 行，模块粒度细（鉴权、检索、客户端、工具各自独立小文件）；前端 19 个文件平均 128 行，但分布极不均匀——**一个文件就占了 59%**。

### 4.2 最大的单点风险：`ChatView.vue` 单文件 1,656 行

| 指标 | 数值 |
| --- | --- |
| 物理行 | 1,656 |
| 代码行 | 1,446 |
| 占前端业务代码比例 | 59% |
| 占 Vue 代码比例 | 68% |

这个文件同时承载了：流式事件解析、消息列表渲染、来源面板、耗时行聚合、模型下拉、历史抽屉、对话内搜索、图片上传、点赞点踩。

**从行数分布看，这是全项目最该拆分的文件**。可行的拆分方向（按职责而非按代码块）：

- 流式接收与事件分发 → 抽成 composable（`useChatStream`）
- 耗时行聚合逻辑 → 独立 composable（`useTiming`）
- 历史抽屉 → 独立组件
- 对话内搜索 → 独立组件

拆分后主文件预计可降到 400 行左右，与其余页面（320 行、213 行）齐平。

### 4.3 注释率偏低，且前后端差异明显

| 类型 | 注释行 / 物理行 | 说明 |
| --- | ---: | --- |
| `.py` | 8.5% | 说明性文字主要写在模块顶部 docstring 与关键函数上 |
| `.vue` | 2.6% | 5 个文件共 59 行注释，其中 `ChatView.vue` 占 54 行 |
